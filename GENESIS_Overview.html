How GENESIS Works — Step by Step

1
You Provide a Target

You enter a URL, IP address, or upload a code repository. GENESIS builds a "Target Intent Brief" — a short internal summary of what needs to be tested and at what depth.

2
It Maps the Attack Surface

Reconnaissance agents scan all open ports, discover sub-domains, list web pages and API endpoints, fingerprint software versions, and detect security controls (like firewalls) — building a complete picture of what is exposed.

3
The AI Forms a Theory

Using extended reasoning (Claude's "think deeply" mode), GENESIS writes a formal hypothesis: what vulnerability it suspects, why, what evidence would confirm it, and how to falsify it if wrong. Hypotheses are saved so the scan can be resumed after a restart.

4
It Runs the Right Tool for the Job

Instead of blindly running every tool, GENESIS picks the exact tool (or writes a custom one-off probe) that best tests the current theory. The tool runs inside an MCP Server — a controlled dispatcher — and results are fed back to the AI. If the result is unexpected, GENESIS updates its theory and tries again with a different approach.

5
A Second AI Reviews the Evidence

Before any vulnerability is marked "confirmed", a separate AI model (Claude Haiku acting as a critic) independently reviews the evidence. It checks: Is the proof real? Is the reasoning sound? Could this be a false positive? If it finds a flaw in the argument, the finding is downgraded to "disputed" and removed from the report.

6
Verified Findings Are Reported

Only confirmed vulnerabilities reach the final report, complete with: severity rating, affected component, proof evidence, step-by-step reproduction instructions, and recommended fix. The live dashboard shows everything in real time; findings are also stored in the database for later review.

Glossary — Key Terms Simply Explained

Vulnerability A weakness in a system that an attacker could exploit to cause harm.
CVE A publicly catalogued, numbered vulnerability (e.g., CVE-2024-1234) shared across the industry.
SQL Injection Tricking a database by inserting code into a text field instead of normal data.
XSS Injecting malicious scripts into a webpage that run in another user's browser.
SSRF Making a server fetch internal resources it should never expose to the outside world.
IDOR Accessing another person's data simply by changing a number in a URL.
Fuzzing Automatically sending random, broken inputs to a program to find crashes and bugs.
Symbolic Execution Mathematically tracing all possible code paths to find conditions that cause failures.
Hypothesis A documented theory about a suspected weakness, written before testing begins.
Exploit A technique or piece of code that actively takes advantage of a vulnerability.
Pentest Short for "penetration test" — an authorised, simulated attack to find weaknesses before real attackers do.
Attack Graph A map showing how individual vulnerabilities connect and chain toward a critical target.
