GENESIS — Step-by-Step Setup Guide
====================================

What You Need Before Starting
-------------------------------
- Docker Desktop for Windows (free, available at docker.com)
- Your Azure AI Foundry API key and endpoint URL
- About 10–15 minutes for the first build

No other software is required. Python, Node.js, and all databases run inside
Docker containers — you do not install them on your machine.


===========================================================================
PART 1 — Install Docker Desktop
===========================================================================

If Docker Desktop is already installed and running, skip to Part 2.

Step 1.1 — Download Docker Desktop
  Go to: https://www.docker.com/products/docker-desktop/
  Click "Download for Windows".

Step 1.2 — Run the installer
  Double-click the installer. When prompted, select:
    ✅ Use WSL 2 instead of Hyper-V  (recommended)
    ✅ Add shortcut to desktop
  Click OK and let the installer finish.

Step 1.3 — Restart your computer
  The installer will ask you to restart. Do so.

Step 1.4 — Start Docker Desktop
  After restarting, open Docker Desktop from the Start menu or desktop shortcut.
  Wait until the whale icon in the system tray (bottom-right corner) stops
  animating. When it is steady, Docker is ready.

Step 1.5 — Confirm Docker is working
  Open PowerShell (Windows key → type "powershell" → press Enter) and run:

    docker --version
    docker compose version

  Both commands should print version numbers. If you see an error, Docker
  Desktop is not running — go back to Step 1.4.

PART 2 — Create Your .env Configuration File
===========================================================================

The .env file stores your database passwords and security keys. It does NOT
store your Azure AI Foundry API key — that goes in the browser later.

Step 2.1 — Open File Explorer and go to:
  C:\Users\AI-SEC-LAB\Desktop\Claude\GENESIS\

  You will see a file called: .env.example

  NOTE: If you do not see it, File Explorer may be hiding files that start
  with a dot. Go to View → Show → Hidden items and check that box.

Step 2.2 — Copy .env.example to .env
  Right-click .env.example → Copy
  Right-click in the same folder → Paste
  Right-click the pasted file → Rename → type exactly:  .env
  Press Enter. (The file name is just ".env" with no ".example" at the end.)

Step 2.3 — Open .env in Notepad
  Right-click .env → Open with → Notepad

  You will see a file with comments and placeholder values. Edit the
  following lines only — leave everything else unchanged:

  ─── Database Passwords ───────────────────────────────────────────
  Find these two lines and replace ChangeMe! with a strong password.
  Use the SAME password in both lines:

    POSTGRES_PASSWORD=ChangeMe!
    MONGODB_PASSWORD=ChangeMe!

  Example:
    POSTGRES_PASSWORD=G3n3sis@Secure2024!
    MONGODB_PASSWORD=G3n3sis@Secure2024!

  You do not need to change DATABASE_URL or MONGODB_URL — Docker
  constructs those automatically from the passwords above.

  ─── Security Keys ────────────────────────────────────────────────
  Find these three lines and set your own values:

    SECRET_KEY=change-me-to-a-very-long-random-string-at-least-32-chars
    API_KEY=my-genesis-access-key-2024
    MCP_API_KEY=my-mcp-internal-secret-2024

  - SECRET_KEY: make it long and random (32+ characters). It does not need
    to be memorable. Example: xK9!mQ2#vL7@nR4$pW1&tY6^uZ8*oA3
  - API_KEY: you will type this in the browser to log in. Pick something
    you will remember. Example: genesis-lab-2024
  - MCP_API_KEY: internal secret between services. Never entered in the
    browser. Make it different from API_KEY. Example: mcp-secret-99xZ

  ─── Leave Everything Else Unchanged ─────────────────────────────
  All other lines (REDIS_URL, CHROMA_HOST, MCP_HOST, STORAGE_PATH, etc.)
  are already correctly configured for Docker. Do not edit them.

  Your Azure AI Foundry API key is NOT placed in .env — it goes in the
  browser settings after the platform starts (see Part 5).

Step 2.4 — Save and close Notepad
  Press Ctrl+S to save. Close Notepad.

PART 3 — Build and Start GENESIS
===========================================================================

Step 3.1 — Open PowerShell as Administrator
  Press the Windows key, type "powershell"
  Right-click "Windows PowerShell" → Run as administrator
  Click Yes when prompted.

Step 3.2 — Navigate to the GENESIS folder

    cd "C:\Users\AI-SEC-LAB\Desktop\Claude\GENESIS"

  Press Enter.

Step 3.3 — Build and start all containers

    docker compose up --build

  Press Enter.

  This command does three things in sequence:
    1. Downloads base images (Python 3.12, Node.js 20, PostgreSQL 16,
       MongoDB 7, Redis 7, ChromaDB) — about 2–3 GB total, takes 5–10
       minutes on first run.
    2. Builds the backend, MCP server, and frontend Docker images —
       installs Python packages, compiles TypeScript, builds React app.
       Takes another 5–8 minutes.
    3. Starts all 8 containers and connects them.

  You will see a long stream of log lines. This is normal. The colours
  indicate which container is printing: backend (blue), frontend (green),
  mcp_server (yellow), databases (white/grey).

  Watch for lines containing ERROR or FAILED. If you see them, go to
  Part 8 (Troubleshooting) at the bottom of this guide.

Step 3.4 — Wait for the ready signal
  The system is ready when you see all three of these lines (they may
  appear in any order, interleaved with other output):

    backend-1        | INFO:     Application startup complete.
    celery_worker-1  | celery@... ready.
    mcp_server-1     | MCP Server running on port 3001
    frontend-1       | /docker-entrypoint.sh: Configuration complete

  This takes about 30–60 seconds after the build finishes.

Step 3.5 — Leave this PowerShell window open
  Do NOT close this window. It keeps all containers running. Minimise it
  and open a new PowerShell window for the next steps.

PART 4 — Verify All Containers Are Running
===========================================================================

Open a NEW PowerShell window (you do not need administrator for this).

Step 4.1 — Check container status

    docker compose -f "C:\Users\AI-SEC-LAB\Desktop\Claude\GENESIS\docker-compose.yml" ps

  Or navigate to the folder first then run:

    cd "C:\Users\AI-SEC-LAB\Desktop\Claude\GENESIS"
    docker compose ps

  You should see 8 rows. The State column should show "running" or "Up"
  for every row. The 8 containers are:

    postgres       — database (PostgreSQL)
    mongodb        — document store (MongoDB)
    redis          — message queue
    chromadb       — vector database
    backend        — Python/FastAPI API server        (port 8000)
    celery_worker  — background task worker
    mcp_server     — security tools server            (port 3001)
    frontend       — React web interface              (port 3000)

Step 4.2 — Check the backend API is responding
  In the same PowerShell window, run (replace YOUR_API_KEY with whatever
  you set as API_KEY in your .env file):

    curl -H "X-API-Key: YOUR_API_KEY" http://localhost:8000/api/v1/settings

  Expected response: a JSON object containing settings keys like
  llm_provider, llm_model, etc. If you see this, the backend is working.

  If you get "connection refused", the backend container has not started
  yet. Wait 30 seconds and try again.

Step 4.3 — Check the MCP security tools server

    curl http://localhost:3001/health

  Expected response:
    {"status":"healthy","tools_count":16,...}

  If you get "connection refused", see Troubleshooting — MCP Server below.

Step 4.4 — Open the web interface
  Open any browser and go to:

    http://localhost:3000

  You should see the GENESIS interface — either a Setup Wizard (first
  time) or the Dashboard. If the page does not load, see Troubleshooting
  below.

PART 5 — Configure the AI Model (Azure AI Foundry)
===========================================================================

This is done in the browser — not in any config file.

Step 5.1 — Open Settings
  In the GENESIS browser interface, click the gear icon or navigate to
  Settings (usually in the left sidebar or top navigation).

Step 5.2 — Go to the LLM tab
  Click the "LLM" tab at the top of the Settings page.

Step 5.3 — Set Provider to Azure AI Foundry
  In the Provider dropdown, select:  Azure AI Foundry

  Additional fields will appear below the model selector.

Step 5.4 — Enter your API Key
  In the "API Key" field, paste your Azure AI Foundry API key.
  This is the key from the Azure Portal → your AI Foundry project →
  Keys and Endpoint section.

Step 5.5 — Select the Model
  In the Model dropdown, select:  claude-sonnet-4-6

  (This is the model ID used by Azure AI Foundry for Claude Sonnet 4.6.
  Use this exact string — it is not a deployment name.)

Step 5.6 — Enter the Endpoint URL
  In the "Endpoint URL" field, enter your Azure AI Foundry endpoint.

  The format is:
    https://YOUR-RESOURCE-NAME.services.ai.azure.com/anthropic

  Your resource name is visible in the Azure Portal. For example:
    https://a-duvermadttl-2478-resource.services.ai.azure.com/anthropic

  IMPORTANT:
  - End the URL with /anthropic (not /v1/messages)
  - If you copy the full curl URL ending in /v1/messages, that is also
    fine — GENESIS strips the suffix automatically
  - Do NOT include a trailing slash after /anthropic

Step 5.7 — Save the LLM settings
  Click the Save button.
  Wait for the green "Settings saved" notification.

Step 5.8 — Test the LLM connection
  Click the "Test Connection" button next to Save.
  Wait 5–10 seconds.

  Success looks like:
    ✅ LLM connection successful  (model: claude-sonnet-4-6, provider: azure)

  If it fails, check:
  - API key is correct and not expired
  - Endpoint URL ends with /anthropic and has no trailing slash
  - Your Azure AI Foundry deployment is active (check Azure Portal)


===========================================================================
PART 6 — Configure the MCP Tool Server
===========================================================================

Step 6.1 — Go to the MCP Server tab in Settings
  Click the "MCP Server" tab.

Step 6.2 — Set the Host
  In the "Host" field, enter:  mcp_server

  ⚠️  Important: Do NOT use "localhost" here.
  Inside Docker, containers talk to each other using service names, not
  localhost. The correct host name is mcp_server (the Docker service name).

Step 6.3 — Set the Port
  In the "Port" field, enter:  3001

Step 6.4 — Save MCP settings
  Click Save.

Step 6.5 — Test the MCP connection
  Click "Test Connection".

  Success looks like:
    ✅ MCP server connection successful

  If it fails, the host is probably set to localhost — change it to
  mcp_server and try again.

Step 6.6 — Check tool availability (optional)
  Click the "Tools" tab in Settings.
  Click "Test All".
  You should see 16 security tools listed. Tools with a green dot are
  installed and ready. Yellow means the tool is installed but has a
  version warning. Red means the tool binary is not found inside the
  container (this may happen with hydra or masscan depending on your
  Docker build).

PART 7 — Run Your First Security Research Session
===========================================================================

⚠️  Only scan targets you have explicit written authorization to test.
   GENESIS will refuse targets set to localhost/loopback addresses.

Step 7.1 — Go to the Dashboard or Sessions page
  Click Dashboard or Sessions in the navigation.

Step 7.2 — Create a new session
  Click "New Session" (or the + button).

Step 7.3 — Enter the target
  In the "Target IP" field, enter the IP address of the machine you want
  to assess. Example:
    192.168.1.100

  This must be a machine you own or have permission to scan.

Step 7.4 — Start the session
  Click Create, then click Start.

Step 7.5 — Watch the AI work in real time
  GENESIS runs a 5-phase autonomous cycle:

    Phase 1 — Reconnaissance
      Runs nmap, masscan, dnsrecon, subfinder to discover open ports
      and services. This is the broadest phase.

    Phase 2 — Service Analysis
      Runs whatweb, curl_probe, openssl_check against discovered
      services to fingerprint technologies and check certificates.

    Phase 3 — Vulnerability Scanning
      Runs nuclei, nikto, gobuster to match known CVEs, check web
      server misconfigurations, and enumerate directories.

    Phase 4 — Exploitation Testing
      Runs sqlmap and xsstrike in check/detection mode only — no
      destructive operations. Verifies whether vulnerabilities are
      actually exploitable.

    Phase 5 — Reporting
      AI synthesises all findings into a structured vulnerability
      report with CVSS scores, CVE references, and remediation steps.

  In the Session Viewer, you can see:
  - Agent Thoughts tab: the AI's reasoning as it decides what to do next
  - Tool Outputs tab: raw output from every security tool run
  - Vulnerabilities tab: confirmed findings appear here in real time

Step 7.6 — Wait for completion
  Sessions typically take 20–40 minutes depending on the target's
  exposure and how many services are discovered. The status bar will
  show the current phase and iteration count.

  When the session completes, the status changes to "Completed" and a
  full vulnerability report is available in the Vulnerabilities page.

PART 8 — Stopping and Restarting GENESIS
===========================================================================

To stop GENESIS:
  Go to the first PowerShell window (where docker compose up is running).
  Press Ctrl+C.
  Wait 5–10 seconds for all containers to shut down cleanly.

To start GENESIS again (fast, no rebuild):
  cd "C:\Users\AI-SEC-LAB\Desktop\Claude\GENESIS"
  docker compose up

  No --build flag needed. Starts in about 30 seconds.
  All your data (sessions, findings, settings) is preserved.

To restart after making code changes:
  docker compose up --build

To wipe all data and start completely fresh:
  docker compose down -v
  docker compose up --build

  WARNING: The -v flag deletes all database volumes, including all
  sessions and vulnerability findings. Use only if something is broken
  and you need a clean state.

PART 9 — Troubleshooting
===========================================================================

─── Problem: docker compose up fails with "Set POSTGRES_PASSWORD in .env" ───
  Your .env file is missing or POSTGRES_PASSWORD is empty.
  Go back to Part 2, confirm the .env file exists (not .env.example) and
  POSTGRES_PASSWORD has a value.

─── Problem: Backend container keeps restarting ──────────────────────────────
  Run this in PowerShell to see the error:
    docker compose logs backend
  Most common cause: DATABASE_URL password in .env does not match
  POSTGRES_PASSWORD. But since docker-compose.yml constructs DATABASE_URL
  automatically from POSTGRES_PASSWORD, this usually means the .env file
  is missing or malformed.

─── Problem: Test LLM Connection fails ───────────────────────────────────────
  Check each of these in order:
  1. API Key: is it pasted correctly with no extra spaces?
  2. Endpoint URL: must end with /anthropic, no trailing slash
     Correct:   https://your-resource.services.ai.azure.com/anthropic
     Wrong:     https://your-resource.services.ai.azure.com/anthropic/
     Wrong:     https://your-resource.services.ai.azure.com/
     Wrong:     https://your-resource.services.ai.azure.com/anthropic/v1/messages
  3. Model: must be exactly  claude-sonnet-4-6
  4. Azure Portal: confirm the deployment is Active and not paused
  5. Did you click Save before clicking Test? Unsaved changes are tested
     directly from the UI — but confirm by checking the Test response.

─── Problem: Test MCP Connection fails ───────────────────────────────────────
  In Settings → MCP Server tab, confirm:
  - Host is set to:  mcp_server  (NOT localhost)
  - Port is set to:  3001
  Then click Save and Test again.

  If it still fails:
    docker compose logs mcp_server
  Look for startup errors.

─── Problem: "Connection refused" on localhost:3000 ─────────────────────────
  The frontend container has not started. Check:
    docker compose ps
  If frontend shows "Exit" or "Restarting", run:
    docker compose logs frontend
  Most common cause: Nginx configuration issue during build.
  Fix: docker compose down && docker compose up --build

─── Problem: "Connection refused" on localhost:8000 ─────────────────────────
  The backend container is not running. Check:
    docker compose ps
    docker compose logs backend

─── Problem: Sessions stay in "pending" and never start ─────────────────────
  The Celery worker is responsible for running sessions. Check:
    docker compose logs celery_worker
  If it shows errors, it is likely a Redis connection issue.
  Confirm Redis is running:
    docker compose ps redis

─── Problem: curl is not recognized in PowerShell ───────────────────────────
  PowerShell has its own "curl" alias (Invoke-WebRequest). Use this instead:
    Invoke-WebRequest -Uri "http://localhost:3001/health" | Select-Object Content
  Or install curl for Windows: https://curl.se/windows/

─── Problem: Docker says "no space left on device" ─────────────────────────
  Docker Desktop has run out of disk space. Open Docker Desktop →
  Settings → Resources → Disk image size → increase it to at least 40 GB.
  Then restart Docker Desktop and try again.

─── Viewing logs for any container ──────────────────────────────────────────
  Replace CONTAINER_NAME with: backend, frontend, mcp_server, postgres,
  mongodb, redis, chromadb, or celery_worker

    docker compose logs CONTAINER_NAME
    docker compose logs --follow CONTAINER_NAME   (live tail)
